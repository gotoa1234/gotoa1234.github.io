<h1>第一部分：Gemini Spark 介紹</h1>

<h2>Step 1：Gemini Spark 是什麼？</h2>
Gemini Spark 是 Gemini 中可持續處理任務的 AI Agent。
<br/>一般對話通常是問一次、回答一次
<br/>Spark 則能建立長期 Task，搭配 Skills 與 Schedules，在背景依固定規則反覆執行，並且 **不用保持電腦開機**。
<br/>※在 2026/10 月份，仍處於 Beta 版，相較於 CodeX、Claude Code 能力較弱(此時客觀意義上的綜和能力)

``` Markdown
Task(任務)：要完成什麼
Skill(技能)：每次應該怎麼做
Schedule(排程)：何時自動執行
```

<br/>以本篇為例：Task 是追蹤台灣市場資訊，Skill 規定來源、分類與輸出格式，Schedule 則負責每天早晚啟動。
<br/><img src="/assets/image/GenerativeAI/2026_10_31/001.png" width="70%" height="70%" />
<br/><br/>


<h2>Step 2：Task、Skill、Schedule 的關係</h2>
Skill 只定義工作方法，本身不會在 07:30 自動醒來
<br/>排程(Schedule) 也不應塞進所有分析規則，否則早晚兩份指令很容易逐漸不一致。


{:class="table table-bordered"}
| 元件 | 本篇設定 | 作用 |
| :--- | :--- | :--- |
| Task | 台灣市場財經資訊彙整 | 保存長期目標與執行脈絡 |
| Skill | taiwan-market-news-brief | 固定資料來源、驗證與報告格式 |
| Morning Schedule | 週一～週六 07:30 | 盤前與隔夜市場早報 |
| Evening Schedule | 週一～週六 19:30 | 台股收盤、公告與晚間新聞 |
| Google Sheet | Market_History | 累積結構化歷史資料 |
| Google Doc | Taiwan_Market_Brief | 保存容易閱讀的完整報告 |

<h2>Step 4：Spark 不是即時行情終端</h2>
當前 Spark 適合新聞搜尋、內容摘要、公告核對與歷史整理，但不應當作券商即時報價系統。

``` Markdown
適合：新聞摘要、公司公告、事件追蹤、早晚報、歷史回顧
不適合：即時下單、秒級價格監控、保證完整的盤中報價、無人監督的交易決策
```

<br/>金融資料可能延遲、缺漏或被模型誤讀，因此每筆重要結論建議 **都必須保存來源網址與資料時間**。

<h1>第二部分：應用場景 & 解決問題</h1>

<h2>Step 1：解決每天手動整理新聞的問題</h2>
我們隨時可以請 AI 協助整理財經資料，來作為資訊同步的方法，但如果能透過自動化的方式，讓 AI 透過排程主動定時推播給我們
<br/>本篇核心在美股、台股開盤前對世界的資訊做個蒐集，流程：

``` Markdown
07:30：查看美股、ADR、匯率、國際財經與台股盤前新聞
盤中：臨時看到大量消息，但沒有統一保存
19:30：整理台股收盤、三大法人、公司公告與晚間新聞
週末：想回顧整週，卻找不到前幾天的資料
```

<br/>進一步延伸，真正耗時的不是每次的搜尋，而是每天重複打開網站、判斷重複新聞、核對時間，再整理成一致格式。
<br/>這點很適合現代 AI 持續整合回報給我們
<br/><br/>


<h2>Step 2：早報與晚報的差異</h2>

{:class="table table-bordered"}
| 時段 | 核心問題 | 主要內容 |
| :--- | :--- | :--- |
| 07:30 早報 | 今天開盤前需要知道什麼？ | 隔夜美股、台灣 ADR、匯率、國際事件、今日公告與行事曆 |
| 19:30 晚報 | 今天市場發生了什麼？ | 指數成交、類股、三大法人、個股事件、盤後公告與隔日觀察 |

<br/>週一~週五有一般交易盤，而週六則是將國際動態持續跟進，實際上可依照需要而調整，甚至週日未開盤期貨仍受國際事件影響。
<br/><br/>


<h2>Step 3：最終工作流</h2>

``` Markdown
公開網站與 Google Search
            ↓
/taiwan-market-news-brief Skill
            ↓
去重、核對時間、分類、來源分級
            ↓
07:30 Morning Brief / 19:30 Evening Brief
            ↓
Google Doc：完整可讀報告
Google Sheet：每日結構化資料
            ↓
週報、趨勢圖與歷史回溯
```

<br/>我們不讓 AI 自動決定買賣，而是讓它把「閱讀與整理」標準化， **最後仍由人判斷**。

<h1>第四部分：建立排程 - 早晚各自匯報</h1>

<h2>Step 1：為什麼拆成兩個 Schedule？</h2>
早報與晚報的目的、資料窗口及錯誤排查都不同，拆開後能分別暫停、立即執行與修改。

``` Markdown
Schedule A：財經早報重點整理｜週一～週六 07:30
Schedule B：財經晚報重點整理｜週一～週六 19:30
Timezone：Asia/Taipei
```

<br/>如果只建立一個「每天兩次」的模糊排程，日後很難確認哪一次失敗，也不方便週末歷史回測、檢查報告內容。
<br/>進入建立排程

| 2. 執行時間 | 一~六 上午 7:30 |
| 3. 使用說明 | 本篇填上以下內容 |


``` Markdown
使用 /taiwan-market-intelligence Skill 執行 Morning Market Brief。
分析目前時間往前約 14 小時內，對全球金融市場與台灣股市具有實質影響的重要事件。
Morning Brief 的主要目標是：
「在台灣股市交易開始前，讓投資人快速理解昨晚全球市場發生什麼，以及今天可能影響台股的主要因素。」
優先分析：
- 美國股市前一交易日表現與美股科技股重要變化
- 美國半導體與 AI 相關企業（NVIDIA、AMD、Apple、Microsoft、Alphabet 等）

- 美國聯準會政策與官員談話、美國公債殖利率、美元指數、USD/TWD
- 美國重要經濟數據、原油/黃金/銅等商品

產出規範與存檔自動化：
1. 依照 Taiwan Market Intelligence Skill 的固定格式輸出 Morning Brief，所有英文資訊整理翻譯為繁體中文，附上來源與可追溯網址。
2. 【歷史歸檔 Google Doc】：在 Google Drive 資料夾「🇹🇼 台灣市場情報歷史日報庫」（資料夾 ID: 1cKv94aVmYt3gxFcpfMLt_qQznM_rZbgW）中建立一份新的 Google 文件，標題命名為「YYYY-MM-DD_早報_市場情報」，並將今日 Morning Brief 完整內容寫入該文件作為永久歷史歸檔。
3. 【視覺化儀表板與資料庫同步】：更新 Google 試算表「🇹🇼 台灣市場情報歷史儀表板」（試算表 ID: 1GuIWr9cfrIujP9SA0nL7jfUzF5br0Lytui-Ng4La5Ro）：
   - 在「Daily_Log」分頁追加 (Append) 一筆新資料：填入日期、版次 (Morning Brief)、全球風險情緒、台股風險情緒、市場風險程度、主要驅動因子、今日核心結論、以及剛建立的 Google Doc 連結。

4. 在 Gemini 對話中呈現晨報內容，並在最後提供本次 Google Doc 歸檔文件連結與 Google 試算表儀表板連結。
```

<h2>Step 4：補充：常見問題與排錯</h2>

{:class="table table-bordered"}
| 問題 | 處理方式 |
| :--- | :--- |
| 看不到 Spark | 檢查帳戶、地區、年齡、訂閱與 Activity 設定 |
| Schedule 沒執行 | 檢查是否 Paused、是否達使用量或同時執行限制 |
| Skill 沒被套用 | 在 Instructions 中明確輸入 `/taiwan-market-news-brief` (自己定義的 SKILL 名稱) |
| Sheets 無法寫入 | 檢查 Workspace 連線、檔案權限與確認提示 |
| 報告出現舊聞 | 加入資料截止時間與前次報告窗口 |
| 數字互相矛盾 | 提高官方來源優先級，矛盾時保留原文並標記待確認 |
| 週六生成假收盤 | 在 Skill 明訂週六週報模式與休市處理 |

<br/>Spark 仍屬 Agent 型功能，可能不準確或執行非預期動作；涉及敏感資料與重大決策時，必須保留人工監督。
