<h1>第一部分：問題描述</h1>

<h2>Step 1：問題描述</h2>
在上篇文章的 <a href="https://gotoa1234.github.io/2026/10/17/1.html#h2_21">第二部分 - Step8. 手動安裝擴充節點後</a>
<br/>重新啟動 Docker 時，運行該工作流會出現以下錯誤：

``` Markdown
ImportError: Numba needs NumPy 2.4 or less. Got NumPy 2.5.
```

<br/><img src="/assets/image/GenerativeAI/2026_10_24/001.png" width="50%" height="50%" />
<br/><br/>

<h2>Step 2：問題原因</h2>
這是因為 Docker 映像在啟動時會執行初始化程序，會重新安裝或更新 Python 套件，導致此問題出現：

``` Markdown
numpy 2.4.6 → numpy 2.5.x
```

<br/>並且出現版本有小於的訊息 **numpy < 2.5**
<br/>如果讀者也有出現相同的狀況，讀者可繼續參考 **本篇的第二部分解法，來解決此問題**
<br/><br/>



<br/><br/>
<h1>第二部分：解決問題 - 建立啟動腳本</h1>

<h2>Step 1：確認目前自己套件版本</h2>
先檢查自己的 ComfyUI 使用的 NumPy、Numba 版本與相依性
<br/>開啟 PowerShell 輸入以下：

``` PowerShell
docker exec comfyui-nvidia /comfy/mnt/venv/bin/python -m pip show numpy numba
docker exec comfyui-nvidia /comfy/mnt/venv/bin/python -m pip check
```

<br/>
<br/>預期會出現

``` PowerShell
docker exec comfyui-nvidia /comfy/mnt/venv/bin/python -m pip show numpy numba
==> 2.5.3
docker exec comfyui-nvidia /comfy/mnt/venv/bin/python -m pip check
==> NOT_FOUND
```

<br/> 2.5.3 是當前的版本號，而  NOT_FOUND 代表沒有既有啟動腳本，我們可以建立新的 user_script.bash ，來做 **啟動腳本**
<br/><img src="/assets/image/GenerativeAI/2026_10_24/002.png" width="100%" height="100%" />
<br/><br/>


<h2>Step 2：建立啟動修復腳本</h2>
因為確定了 NOT_FOUND 沒有啟動腳本，那麼我們可以選擇新增的方式 (如果已有存在則是將下列腳本編輯添加)

``` PowerShell
#!/bin/bash
set -e
/comfy/mnt/venv/bin/python -m pip install --disable-pip-version-check --no-deps "numpy==2.4.6"
```

<br/>然後再執行 Docker 啟動指令，將 NumPy 恢復成原來的 2.5.3

``` PowerShell
docker exec --user ubuntu comfyui-nvidia /comfy/mnt/venv/bin/python -m pip install --no-deps --force-reinstall "numpy==2.5.3"
```

<br/>最後重新啟動 (※comfyui-nvidia 是我的 ComfyUI 的容器名稱)

``` PowerShell
docker restart comfyui-nvidia
```
