<h1>第一部分：認識 AI Agent 與準備工作</h1>

<h2>Step 1：這篇適合誰？</h2>
這篇文章是寫給第一次接觸 AI Agent 的讀者。不需要另外安裝 Claude Code CLI。 
<br/>**會部分使用到終端機(Command Line)、與安裝 Node.js**
<br/>只要會安裝 Windows 軟體、選擇資料夾及閱讀檔案修改內容，照著操作執行指令，就能完成 Claude Code Skill 操作。

``` Markdown
這篇會完成：
1. 安裝 Claude Desktop
2. 從 Code 頁籤開啟本機專案
3. 使用別人製作的 Skill
4. 看懂 Claude 準備執行的動作
5. 如何快速建立並呼叫自己的 Skill
```

<br/><br/>


<h2>Step 2：AI 聊天機器人與 AI Agent 有什麼不同？</h2>
**一般 AI 聊天機器人** ： 主要一對一回答問題
<br/>**AI Agent** ： 除了回答，也能在取得允許後讀取資料、操作工具、修改檔案並驗證成果。

{:class="table table-bordered"}
| 比較 | 一般 AI 對話 | AI Agent |
| :--- | :--- | :--- |
| 主要用途 | 問答、翻譯、產生文字 | 完成多步驟任務 |
| 專案內容 | 通常要手動貼進對話 | 可直接讀取允許的專案資料夾 |
| 修改檔案 | 回答後由使用者複製 | 可提出或直接建立修改 |
| 執行工具 | 通常有限 | 可搜尋、執行測試或使用擴充工具 |
| 使用者責任 | 確認答案是否正確 | 還要確認權限、命令與檔案變更 |

<br/>因此 AI Agent 並不是「完全自動、永遠正確」。它比較像速度很快的新進協作者，能完成工作，但仍需要清楚範圍、適當權限與人工驗收。
<br/>本篇要說明如何讓 AI Agent 匯入 SKILL （技能 / 工具），精準達成自動化目標。

<h2>Step 6：建立安全的練習資料夾</h2>
首次使用建議 **不要** 直接選擇公司正式專案、私人照片、雲端同步根目錄或存有密碼的資料夾。
<br/>可在某個槽、或者桌面建立：

``` Markdown
ClaudeCodePractice/
├─ README.md
└─ SKILL.md
```

<br/>在 `README.md` 隨意寫一段專案說明，在 `SKILL.md` 未來如果建立自己的 SKILL 資訊。
<br/>※如此隔離此練習資料夾的好處： **未來即使被修改，也不會影響重要資料。**

<h1>第三部分：快速使用別人製作的 Skill</h1>

<h2>Step 1：Skill 是什麼？</h2>
Skill 是一套可以重複使用的說明、知識或工作流程。
<br/>Claude 會在需求符合時自動載入，也可以由使用者輸入 `/skill-name` 手動呼叫。

``` Markdown
普通 Prompt：
只存在目前對話，下一次可能要重新輸入

Skill：
保存成 SKILL.md，可跨對話重複使用，也能交給團隊共同維護
```

<br/>Skill 本身不一定增加新的工具。它主要告訴 Claude「遇到這類任務時，應依什麼流程、限制與格式工作」。
<br/><img src="/assets/image/GenerativeAI/2026_09_19/004_3.png" width="50%" height="50%" />
<br/><br/>

<h2>Step 3：首次演練 - 引入藝術宣言 SKILL - canvas-design</h2>
為了快速上手 SKILL 如何使用，我們先從 canvas-design 這個 SKILL 的引用說明
<br/>依序選擇 -> 分類:圖像 -> 選擇：canvas-design anthropics/skills (安裝量約：102.8K ; 按★數：172.5K)
<br/>※如果用輸入框查詢會有相同名稱的 **canvas-design** 會造成混淆 
<br/><img src="/assets/image/GenerativeAI/2026_09_19/005_1.png" width="100%" height="100%" />
<br/>
<br/>以下是擷取自此 SLILL.md 的說明，最重要的是 **不會抄襲既有藝術家的作品——設計必須原創，以避免侵犯著作權。**

``` Markdown
兩步驟的視覺設計：先以文件形式發明一套設計哲學，再把該哲學表現在畫布上，而不是填一份範本。

- 第一步是一份 .md 檔，用一到兩個字為這場運動命名，並以四到六段文字闡述，寫得夠通用以便他處重用。
- 只輸出 .md、.pdf 與 .png，除非另有要求否則只有一頁，哲學檔案與作品一併交付。
- 要求進行第二輪，且不畫任何新東西——指示是讓既有構圖更為一體，而不是加一個形狀、一個濾鏡或另一種字型。
- 到 ./canvas-fonts 目錄找字體，並把元素重疊或任何超出畫布邊界的東西視為沒有商量餘地的失敗。
- 不會抄襲既有藝術家的作品——設計必須原創，以避免侵犯著作權。
```

<h1>第四部分：建立自己的第一個 Skill</h1>

<h2>Step 1：從反覆出現的 Prompt 找題目</h2>
適合做成 Skill 的內容，通常是已經重複輸入過幾次的 Prompt，例如：

``` Markdown
- 每篇文章都要檢查 Front Matter、標題與圖片路徑
- 每次 Commit 前都要整理修改摘要
- 每次建立 API 都要符合相同命名與錯誤格式
- 每次發佈前都要跑同一份檢查清單
```

<br/>本篇示範建立 `/stock-technical-analyzer`，用來查找台股、美股特定股票代號，與參照固定分析規則。它不會自動修改檔案，適合新手首次建立 Skill 的練習。
<br/><br/>



<h2>Step 2：與 Claude 討論 Skill 骨架</h2>
最快的方式是與 AI 討論自己的功能，我們練習的目標是：**將布林通道、RSI、交易量當基礎策略建立 SKILL **
<br/>輸入以下對話式詢問：

``` Markdown
我想要寫一個自己專屬的 Skill.md ，目標是使用此 Skill 可以查詢某個股票，
```

<h2>Step 3：Skill 不等於絕對可信</h2>
Skill 是文字與相關資源組成的操作指示。陌生 Skill 可能包含不適合目前環境的命令，甚至引導 Agent 讀取或傳送敏感資料。

``` Markdown
使用別人 Skill 前：
1. 閱讀完整 SKILL.md
2. 查看是否包含 scripts 或可執行檔
3. 搜尋 download、upload、delete、token、secret、env 等關鍵字
4. 確認會連線到哪些網站與服務
5. 先在沒有秘密的練習專案測試
```

<br/>即使 Skill 來自可信作者，也可能因版本、Windows 相容性或專案差異而不適用。
